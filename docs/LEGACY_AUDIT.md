## 3. ข้อค้นพบที่กระทบสถาปัตยกรรม

### 3.1 ระบบเดิมไม่มี "ใบหน้านี้คือใคร" รายใบหน้า

ไม่มีตารางผูก `faces` กับ `persons` บุคคลถูกกำหนดด้วยใบหน้าตัวอย่างใน `person_embeddings` แล้วระบบคำนวณความคล้าย
(cosine ≥ 0.45, เอาค่าสูงสุดจากทุกตัวอย่าง) **ใหม่ทุกครั้งที่ค้น** (`app/services/search_service.py:70-146`)

ผลต่อการย้ายข้อมูล:

- สิ่งที่ผู้ใช้ยืนยันจริงในระบบเดิมมีแค่: รายชื่อ, กลุ่ม, ใบหน้าตัวอย่าง 522 ใบ, คำปฏิเสธ 178 รายการ, ใบหน้าที่ทิ้ง 335 ใบ
- "รูปของคนนี้" ในระบบเดิมเป็นผลคำนวณ ไม่ใช่คำยืนยัน → ในคลังใหม่ต้องเป็น **ข้อเสนอ AI รอตรวจ** ไม่นับเป็น "ยืนยันแล้ว"
- 512 จาก 522 ใบหน้าตัวอย่างมีเวกเตอร์ตรงกับแถวใน `faces` ทุก byte และ 510 ใบมี `photo_path` อยู่ใน `photos`
  → ผูกกลับเป็นใบหน้าในรูปได้และถือเป็นคำยืนยันที่มีที่มา (`decision_origin = legacy_sample`); อีก 10–12 ใบเก็บเป็นตัวอย่างภายนอก

### 3.2 พิกัดกรอบใบหน้า

`bbox` เป็นพิกเซล `[x1, y1, x2, y2]` ในพื้นที่ของภาพขนาดเต็ม (`face_service.py:123-128` คูณกลับจากภาพที่ย่อเหลือด้านยาว 1280)
ภาพถูกอ่านด้วย `cv2.imdecode(…, IMREAD_COLOR)` ซึ่งตามค่าเริ่มต้นของ OpenCV หมุนตาม EXIF แล้ว
→ **สมมติฐาน: พิกัดอยู่บนภาพที่หมุนแล้ว** ตรงกับ convention ของคลังใหม่ ยังไม่ได้พิสูจน์ด้วยรูปแนวตั้งจริง (ดู "ยังไม่ทราบ")

การแปลงเป็นสัดส่วน [0,1] ต้องรู้ขนาดภาพ แต่ 1,908 รูปไม่มีขนาดในฐาน → ต้องอ่านจากไฟล์จริง

### 3.3 เวกเตอร์ใบหน้า

- ทุกแถว (`faces` 45,853 + `person_embeddings` 522) ยาว 2,048 bytes = 512 มิติ `float32`
- เก็บค่า `face.embedding` ดิบ **ไม่ normalize**; normalize ตอนคำนวณ (`search_service.py:28-31`)
- มาจาก `w600k_mbf.onnx` (MobileFaceNet, ชุดข้อมูล WebFace600K ตามตารางของ InsightFace)
  SHA-256 `9cc6e4a75f0e2bf0b1aed94578f144d15175f357bdc05e815e5c4a02b319eb4f`
- ตัวตรวจใบหน้า `det_500m.onnx` (SCRFD-500M) SHA-256 `5e4447f50245bbd7966bd6c0fa52938c61474a04ec7def48753668a9d8b4ea3a`
- ก่อนตรวจ: ย่อภาพให้ด้านยาว ≤ 1280 ด้วย `INTER_AREA`, `det_size = 640×640`

การใช้เวกเตอร์เดิมต่อใน Rust เป็นไปได้ก็ต่อเมื่อ pipeline ใหม่ให้เวกเตอร์ใน space เดียวกันจริง (โมเดลเดียวกัน + ย่อ/จัดหน้า/ครอปแบบเดียวกัน)
ต้องพิสูจน์ด้วยการเทียบ cosine ระหว่างเวกเตอร์เดิมกับที่ Rust สร้างจากใบหน้าเดียวกัน **ยังไม่ได้ทำ**

## 5. สิ่งที่ยังไม่ทราบ

1. พิกัดกรอบของรูปแนวตั้งอยู่บนภาพที่หมุนแล้วจริงหรือไม่ — ต้องเทียบกับรูปจริงอย่างน้อยหนึ่งรูปที่ EXIF orientation ≠ 1
2. เวกเตอร์ที่ Rust + ONNX Runtime สร้างจะอยู่ใน space เดียวกับของเดิมหรือไม่
3. เนื้อหาของฐานเก่ากว่า (`PhotoSearch/photosearch.db`) และควรรวมหรือไม่
4. เจ้าของผลิตภัณฑ์ต้องการแจกโมเดลชุดเดิมต่อหรือไม่ (ข้อ 3.4)
5. ผู้ใช้คนอื่นของแอปเดิมมีฐานข้อมูลรุ่นใด — ตรวจเฉพาะเครื่องนี้

## 6. สิ่งที่มีแล้วในรุ่น Rust

`puri_core::legacy::dry_run` (คำสั่ง `preview_legacy_import`) เปิดฐานเดิมแบบอ่านอย่างเดียว ตรวจว่าเป็น schema ที่รู้จัก
แล้วรายงานจำนวนข้างต้นพร้อมจำนวนรูปที่หาไฟล์ไม่เจอ รันกับฐานจริงแล้วได้ตัวเลขตรงกับหมวด 2 และ SHA-256 ของไฟล์ฐานเดิมก่อน–หลังรันเท่ากัน
**ยังไม่นำข้อมูลเข้าคลังใหม่** แผนขั้นต่อไปอยู่ใน [MIGRATION.md](MIGRATION.md)
