## แอปจริง (`e2e/run.sh` + `e2e/smoke.js`)

debug build ฉีดสคริปต์เข้า WKWebView ของหน้าต่างจริง สคริปต์กดและพิมพ์ผ่าน DOM ทุกคำสั่งไปถึง Rust ผ่าน IPC จริง
คลังและโฟลเดอร์รูป (17 ไฟล์จาก `make_fixtures`) สร้างใหม่ในโฟลเดอร์ชั่วคราว ไม่แตะคลังหรือรูปจริงของผู้ใช้

รันสองแบบ ผ่านทั้งสองแบบ:

- `SHOTS=1 e2e/run.sh` — `pnpm tauri dev` (Vite dev server + `devCsp`)
- `APP="target/debug/bundle/macos/Puri Photo Search.app/Contents/MacOS/puri-photo-search" e2e/run.sh` —
  `.app` จาก `pnpm tauri build --debug --bundles app` (31 MB, asset ฝังในแอป, CSP ของ production)

## วิเคราะห์ใบหน้าอัตโนมัติในแอป

### เทสต์อัตโนมัติ (`crates/core/tests/faces_ai.rs`)

ใช้ตัววิเคราะห์จำลองที่มีเฉพาะในโค้ดเทสต์ ("บุคคล" ของรูปทดสอบกำหนดจากค่าสี) และชุดโมเดลจำลองที่ "ดาวน์โหลด" ผ่าน `file://`
ด้วยงานติดตั้งตัวจริง — เทสต์นี้พิสูจน์กติกาข้อมูลรอบ AI ไม่ใช่ความแม่นยำของโมเดล

| เทสต์ | สิ่งที่พิสูจน์ |
|---|---|
| `model_is_optional_then_one_click_install_analyses_existing_photos` | ไม่มีโมเดล: เพิ่มและดูรูปได้ครบ, "ยังไม่ได้วิเคราะห์" ≠ "ไม่พบใบหน้า" (T09); ติดตั้งด้วยคำสั่งเดียว (กดซ้ำได้งานเดิม) → เก็บเฉพาะไฟล์ที่ใช้ → รูปเดิมถูกวิเคราะห์ต่อเอง; สแกนซ้ำ/เปิดใหม่ไม่เกิดใบหน้าซ้ำ; รูปใหม่ถูกวิเคราะห์ในงานเดียวกับการเตรียมข้อมูล |
| `corrupt_download_is_refused_and_can_be_retried` | ไฟล์ที่ checksum ไม่ตรงไม่ถูกใช้ งานล้มเหลวพร้อมเหตุผล; ดาวน์โหลดใหม่แล้วใช้ได้ |
| `suggestions_are_never_confirmations_and_review_acts_only_on_selected_faces` | กลุ่มใบหน้าไม่ใช่บุคคล; ข้อเสนอไม่นับเป็นรูปของบุคคลและไม่อยู่ในผลค้น (T18); ยืนยันเฉพาะใบที่เลือก (S16 Acceptance 1); คิวของ revision เก่าได้ `PREVIEW_STALE`; ปฏิเสธข้อเสนอแล้วไม่เสนอซ้ำแม้เปิดใหม่ (T19); "ไม่ใช่ใบหน้า" ไม่กลับมาเมื่อสแกนซ้ำ |
| `manual_labels_survive_analysis_and_gain_an_embedding` | กรอบที่วาดเองและคำยืนยันไม่ถูกทับเมื่อวิเคราะห์ ไม่มีกรอบซ้ำ และกลายเป็นตัวอย่างให้เสนอใบอื่น (T22 บางส่วน) |
| `legacy_people_import_is_read_only_idempotent_and_only_suggests` | ฐานเดิมไม่ถูกแก้แม้ byte เดียว; retry และรันซ้ำไม่สร้างคนซ้ำ (T29 บางส่วน); ชื่อซ้ำเป็นคนละคน; เวกเตอร์เดิมไม่ถูกใช้; ภาพตัวแทนจากใบหน้าตัวอย่าง; ข้อเสนอจากข้อมูลเดิมไม่นับเป็นยืนยันแล้วจนกว่าผู้ใช้ยืนยัน |
| `review_list_stays_usable_while_analysis_adds_faces` | รายการของคิวที่เปิดอยู่ยังขอได้หลังมีรูปใหม่ถูกวิเคราะห์เสร็จ (เดิมได้ `PREVIEW_STALE` ทุกครั้งระหว่างงานวิเคราะห์); คิวรอบถัดไปเห็นใบหน้าใหม่; เก็บบุคคลออกจากรายชื่อแล้วข้อเสนอของคนนั้นหายและรายการเดิมเก่า — เทสต์นี้ล้มเมื่อถอนตัวแก้ออก |
| `face_crops_are_ready_after_analysis_without_reopening_originals` | มีไฟล์ครอปหนึ่งไฟล์ต่อใบหน้าที่ตรวจพบตั้งแต่งานวิเคราะห์จบ; ขอ `face/{id}` ได้แม้โฟลเดอร์รูปถูกย้ายออก |
| `low_confidence_detections_are_not_suggested_or_clustered_but_can_be_named` | ใบหน้าที่คะแนนตัวตรวจต่ำกว่า 0.6 ไม่ได้ข้อเสนอชื่อ (ทั้งในคิวและตัวดูภาพ) และไม่ถูกจับกลุ่ม แต่กรอบยังอยู่ นับเป็นใบที่ยังไม่มีชื่อ และผู้ใช้ตั้งชื่อเองแล้วค้นเจอทันที — เทสต์นี้ล้มเมื่อถอนตัวกรองออก |
| `library_from_v1_upgrades_in_place` | คลัง schema 1 ของรุ่น alpha.1 เปิดได้และข้อมูลครบหลังอัปเกรดเป็น schema 2 |

**ไล่ดูข้อเสนอด้วยตา** (ทำแผ่นรวมครอปของทั้ง 14 กลุ่มเทียบกับภาพตัวแทน — ไม่ใช่การวัดความแม่นยำ ไม่มีชุดคำตอบ และผู้ตรวจไม่รู้จักบุคคลในรูป
จึงบอกได้แค่ว่าครอปในกลุ่ม "ดูเป็นคนเดียวกับภาพตัวแทน" หรือไม่):

- 12 กลุ่ม (รวม 4 กลุ่มใหญ่ 109 / 89 / 37 / 35 ใบ) ครอปที่ดูทั้งหมดสอดคล้องกับภาพตัวแทน ใบที่ติดป้าย "ควรตรวจสอบ" คือหน้าใส่หน้ากากอนามัย หันข้าง หรือเบลอ
- 1 กลุ่ม (4 ใบ ทุกใบป้าย "ควรตรวจสอบ") **ผิดชัดเจน**: เป็นท้ายทอย/ด้านข้างศีรษะ ที่ตัวตรวจใบหน้าให้คะแนน 0.50–0.54 (ติดเกณฑ์ขั้นต่ำ 0.5) จับคู่กับภาพตัวแทนที่เบลอมาก
- 1 กลุ่ม (1 ใบ ป้าย "ใกล้เคียงมาก") ตัดสินจากภาพไม่ได้ว่าใช่คนเดียวกับภาพตัวแทนหรือไม่
- กลุ่มยังไม่ทราบชื่อ: กลุ่มใหญ่ที่เปิดดูเป็นคนเดียวกันทั้งกลุ่ม แต่พบหนึ่งกลุ่ม (11 ใบ) ที่เป็น**ใบหน้าเบลอนอกโฟกัสของหลายคน**ถูกจับรวมกัน
- ใบหน้าที่คะแนนตัวตรวจต่ำกว่า 0.6 มี 176 จาก 1,099 ใบ — เป็นแหล่งของข้อเสนอผิดข้างบน

**หลังใส่ตัวกรองคะแนนตัวตรวจ ≥ 0.6** (เจ้าของผลิตภัณฑ์ตัดสินให้กรอง; สร้างคลังทดสอบใหม่จากรูปชุดเดิม 292 รูป + นำรายชื่อเข้าใหม่):

| | ก่อนกรอง | หลังกรอง |
|---|---|---|
| กลุ่มที่ AI เสนอชื่อ | 14 กลุ่ม / 331 ใบ | 13 กลุ่ม / 326 ใบ — กลุ่มท้ายทอย 4 ใบที่ผิดหายไป |
| กลุ่มยังไม่ทราบชื่อ | 140 กลุ่ม | 110 กลุ่ม / 440 ใบ |
| ใบที่ยังไม่เข้ากลุ่มใด | 197 | 333 (รวมใบคะแนนต่ำ 176 ใบ) |
| ใบคะแนนต่ำกว่า 0.6 ที่อยู่ในคิว | ไม่ได้นับ | 0 จาก 766 ใบในคิว (ตรวจทุกใบกับฐานข้อมูล) |

เปิดแผ่นรวมครอปของกลุ่มยังไม่ทราบชื่อ 16 กลุ่มใหญ่สุดหลังกรอง: ไม่มีกลุ่ม "หน้าเบลอรวมกัน" แล้ว 15 กลุ่มดูเป็นคนเดียวกันทั้งกลุ่ม
อีก 1 กลุ่ม (10 ใบ) ดูเหมือนมีมากกว่าหนึ่งคนปนกัน งานรอบนี้ใช้ 32.1 วินาที (รอบก่อน 25.1 — วัดรอบละครั้ง เครื่องไม่ได้ว่างเท่ากัน)

พบและแก้ระหว่างรอบนี้: ช่องเลือกบุคคลไม่ไฮไลต์รายการใดเมื่อคลังมีรายชื่ออยู่แล้วและผลค้นเปลี่ยน ทำให้พิมพ์ชื่อใหม่แล้วกด Enter ไม่เกิดอะไร
(e2e ไม่เจอเพราะคลังทดสอบเริ่มจากไม่มีบุคคล) — แก้ให้รายการแรกที่แสดงอยู่ถูกเลือกเสมอ แล้วทดสอบซ้ำในหน้าจอผ่าน

ยังไม่ได้ทดสอบ: ตัววิเคราะห์ใบหน้าใน release build ที่แจก (ทดสอบใน bundle debug ที่เซ็นแบบเดียวกัน และ dev bridge แบบ release — ดูหมวดตัวติดตั้ง), Mac Intel (compile ผ่านเท่านั้น),
คลังใหญ่กว่า 292 รูปพร้อมวิเคราะห์ใบหน้า, การพักงานดาวน์โหลดโมเดล, เน็ตหลุดกลางทาง, หน้าตรวจสอบระหว่างที่งานวิเคราะห์กำลังวิ่งจริง
(งาน 292 รูปจบใน 25 วินาทีก่อนเปิดหน้า — กติกานี้มีเทสต์อัตโนมัติยืนยันแทน)

## ตัวติดตั้ง macOS ที่เซ็นแล้ว (`scripts/release-mac.sh`)

รันบนเครื่องพัฒนาด้วยใบรับรอง Developer ID และโปรไฟล์ notarytool จาก keychain

| ตรวจ | ผล |
|---|---|
| build | universal (`x86_64 arm64`), แอป 22 MB, DMG 13.2 MB |
| ลายเซ็นแอป | `codesign --verify --deep --strict` ผ่าน; Developer ID Application, hardened runtime |
| notarize | Apple ตอบ `Accepted`; staple และ `stapler validate` ผ่าน |
| Gatekeeper | `spctl -a -t install` (DMG) และ `spctl -a -t exec` (แอป): `accepted, source=Notarized Developer ID` |
| เนื้อหา | ไม่มี ONNX Runtime หรือไฟล์โมเดลในแอป |
| เปิดแอป release | เปิดด้วย `HOME` ชี้โฟลเดอร์ชั่วคราว: หน้าต่างขึ้นหน้าเริ่มต้น ฟอนต์และภาพครบ คลังถูกสร้างในโฟลเดอร์ชั่วคราว (คลังจริงของเครื่องไม่ถูกสร้าง) |

หลังเผยแพร่ `v2.0.0-alpha.1`: ดาวน์โหลดไฟล์จากลิงก์สาธารณะแบบไม่ล็อกอินด้วย `curl` → SHA-256 ตรงกับ `SHA256SUMS.txt`, `stapler validate` ผ่าน,
`spctl` รับทั้ง DMG และแอปข้างใน (`Notarized Developer ID`), แอปเป็น `x86_64 arm64` รุ่น 2.0.0-alpha.1 ขั้นต่ำ macOS 12.0

ยังไม่ได้ทำ: ติดตั้งจาก DMG ที่ดาวน์โหลดผ่านเบราว์เซอร์ (มี quarantine flag) บนเครื่องอื่น, Intel Mac, macOS รุ่นต่ำกว่า 26,
และ e2e กับ release build (hook ทดสอบมีเฉพาะ debug build)

### รุ่น 2.0.0-alpha.2 (workflow `Release` บน GitHub Actions)

ตั้งแต่รุ่นนี้ตัวติดตั้งที่เผยแพร่สร้างบน GitHub Actions ไม่ใช่เครื่องพัฒนา ก่อนติด tag ตรวจสองทาง (18 พ.ย. 2569):

**bundle debug ที่เซ็นแบบเดียวกับตัวที่แจก** (`pnpm tauri build --debug` ด้วย Developer ID, hardened runtime, ไม่มี entitlement — มี hook ทดสอบ)

| ตรวจ | ผล |
|---|---|
| ตัววิเคราะห์ใบหน้าจริง (ONNX Runtime + `buffalo_l`) | ติดตั้งโมเดลจาก zip ในเครื่อง 5.9 วินาที → เพิ่มโฟลเดอร์จริง 24 รูป → 30 ใบหน้า (9 กลุ่ม + 1 ใบเดี่ยว เท่ากับผลใน `pnpm tauri dev`), ครอปใบหน้า 256×256 แสดงผ่าน `puri://` |
| `e2e/run.sh` (`APP=…`) | ผ่าน 14 ขั้น ต้นฉบับไม่เปลี่ยน |

**ตัวติดตั้งรอบซ้อมจาก workflow** (`workflow_dispatch` บน branch ของรุ่น — build + เซ็น + notarize แต่ไม่เผยแพร่)

| ตรวจ | ผล |
|---|---|
| notarize | Apple ตอบ `Accepted`; `stapler validate` ผ่านทั้งบน runner และบนเครื่องนี้ |
| Gatekeeper | `spctl` รับทั้ง DMG (`-t install`) และแอปข้างใน (`-t exec`): `Notarized Developer ID` |
| ลายเซ็นแอป | `codesign --verify --deep --strict` ผ่าน; hardened runtime; ไม่มี entitlement |
| เนื้อหา | `x86_64 arm64`, รุ่น 2.0.0-alpha.2, ขั้นต่ำ macOS 13.4, แอป 40 MB, DMG 18.9 MB; ONNX Runtime ลิงก์อยู่ในส่วน arm64 เท่านั้น; ไม่มีไฟล์โมเดล |
| เปิดแอป release | เปิดด้วย `HOME` ชี้โฟลเดอร์ชั่วคราว: ขึ้นหน้าเริ่มต้นพร้อมโลโก้ใหม่และการ์ดดาวน์โหลดตัววิเคราะห์ใบหน้า คลังถูกสร้างในโฟลเดอร์ชั่วคราว (คลังจริงของเครื่องไม่ถูกสร้าง) |

ไม่ได้ทำ: กดดาวน์โหลดโมเดลและวิเคราะห์ใบหน้าในแอป release เอง (ไม่มี hook ทดสอบใน release — ยืนยันผ่าน bundle debug ที่เซ็นแบบเดียวกันแทน)
